# 0012 — DCSS: upstream's WebTiles client against a headless game in the worker

**Decision.** DCSS is built as upstream's headless WebTiles game (upstream's Makefile, cross-compiling mode, no patches); its socket is replaced at link time by the Web Worker. The game is shown with upstream's own WebTiles client, version-matched and unmodified, in a same-origin iframe. A small host script provides what a WebTiles lobby provides. The shell adds a start screen, a status band, the message log and context-aware touch controls, all derived from the same message stream.
**Alternatives.** A console (curses) build with our own cell renderer, as for Brogue: full control, but DCSS's console UI is an 80×24 terminal and we would re-implement tiles, menus and popups. A local-tiles (SDL) build: the tiles look, but SDL/GL emulation in the browser and no DOM menus.
**Consequences.** Every DCSS screen (character creation, menus, descriptions, the character sheet, the level map, targeting) works as on the official servers, and updates bring the matching client along. Menus and descriptions are already DOM text, which phones can restyle and scroll. Phone work is CSS plus a few presentation hooks in the host. The port depends on the WebTiles protocol and client modules; `tests/conformance/upstream-drift.ts` watches exactly those.
