# NetHack — feasibility report

Status: **port implemented** (catalog status `experimental`). Licensing is reported in [`games/nethack/LICENSES.md`](../../games/nethack/LICENSES.md); how the port works is in [`games/nethack/PORTING.md`](../../games/nethack/PORTING.md).

## The three release-readiness questions

| Question | Answer | Evidence |
|---|---|---|
| Can it technically run in a browser? | **Yes.** | Upstream maintains a WebAssembly build (`make CROSS_TO_WASM=1`, "Case sample: Web Assembly" in `Cross-compiling`) with a "shim" window port that calls JavaScript for every window operation. At 5.0.0 it no longer links; one small patch (below) fixes that, and the pinned source then builds with the project's pinned Emscripten (6.0.13) in about a minute and a half. In Node, the module starts a game, runs character creation, prints the introduction and "welcome to NetHack! You are a lawful dwarven Valkyrie." and draws the first level. |
| Can Rogue Archive legally redistribute everything it ships? | **Yes**, under the NetHack General Public License (NGPL). | The game, its data files and the tiles (`win/share/*.txt`, by Warwick Allison and others, distributed with NetHack) are all under the NGPL; Lua (embedded for level descriptions) is MIT. A full licence report goes in `games/nethack/LICENSES.md` with the port. |
| Can it deliver a polished experience? | **Plausibly; to be shown.** | NetHack's window interface (`doc/window.txt`) separates the map, messages, status, menus, text windows and prompts, so a port can lay them out for phones and render the map as text or tiles. The command set is large (about 100 commands, many with item or direction prompts): the touch controls need the same audit as the other games. |

## Findings

- **Build:** upstream's web build reads its own Makefiles and hints (`hints/linux.500`, `CROSS_TO_WASM=1`). Two changes on the command line, none in the source: two new compiler warnings that upstream's `-Werror` turns into errors (`-Wno-unused-but-set-global`, `-Wno-unused-command-line-argument`), and `HACKDIR=/` (the game data is embedded at the module's root; upstream's default bakes the builder's home directory into the binary).
- **One patch** (`games/nethack/patches/0001-libnh-catch-up-with-unixmain.patch`): `sys/libnh/libnhmain.c`, the web build's replacement for `sys/unix/unixmain.c`, has fallen behind it. It defines `after_opt_showpaths()` again (now in `src/earlyarg.c`: a duplicate symbol), keeps `whoami()` static although `earlyarg.c` calls it, and lacks `get_nhuuid()`/`free_nhuuid()` (the last two are hidden at link time by upstream's `ERROR_ON_UNDEFINED_SYMBOLS=0` and abort at start). No game rules change.
- **Window port:** the shim calls one JavaScript function for each window operation (`shim_create_nhwindow`, `shim_print_glyph`, `shim_putstr`, `shim_select_menu`, `shim_yn_function`, `shim_getlin`, `shim_status_update`, `shim_nh_poskey`...) and waits for its answer with Asyncify. The port implements these in the worker: the map, message line and status are composed into the classic 80×24 layout (as NetHack's tty port draws it), and menus and text windows become sheets with tappable lines. Some return types are handled by upstream's helpers in quirky ways (a returned string is written over the return pointer; only empty strings are safe), so the port avoids returning strings.
- **Tiles and text:** each `print_glyph` call carries the glyph's `glyph_info` (character, colour and tile index). Text uses the character and colour; tiles use the tile index into upstream's tile set (1,515 16×16 tiles: 789 monsters, 483 objects, 243 others), converted at build time with upstream's tile tools. Both can be offered, as Brogue's and Rogue's ports do.
- **Saves:** NetHack saves to `save/` under its directory (`/save` here) when you save with `S`; `/record`, `logfile`, `xlogfile` and `livelog` hold scores. Whether its level-file checkpoints let a game survive a closed page is to be checked. The worker mounts these on IndexedDB (IDBFS). Whether desktop NetHack 5.0.0 can open these save files (32-bit WebAssembly against 64-bit desktop builds) is to be tested before it is offered.
- **Size:** 6.3 MB of WebAssembly with the game data embedded (2.2 MB gzipped), 0.09 MB of JavaScript.
- **Engine equivalence:** NetHack's random number generator can be seeded on the command line in debug builds; the conformance harness (as for the other ports) should drive a seeded game natively and in Node and compare the screens.

## Risks

| Risk | Mitigation |
|---|---|
| The shim's Asyncify callback is not re-entrant (a second window call before the first answers crashes) | The worker answers every call before the next can start; the shim already reports violations. |
| Upstream's web build bit-rots further | Pin the release; the drift check names the shim functions and the files the patch touches; a weekly canary builds the next release. |
| Save compatibility with 64-bit desktop builds | Test with a desktop 5.0.0 save before advertising it. |
| A large command set on phones | Controls audit (as for the other games): context-aware dock, fans, item prompts as lists. |
